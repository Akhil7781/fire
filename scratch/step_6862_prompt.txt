## Task 2 — Native-Raster Footprint Verification

The previous audit constructs a 5.12 km × 5.12 km footprint using geodesic offsets from chip centers. However, Sentinel-2 chips are aligned to native UTM raster grids, not necessarily to the geographic axis-aligned approximation.

Investigate whether the repository contains sufficient information to reconstruct the actual chip footprints, including:

* MGRS tile identifiers.
* UTM zone and CRS.
* Pixel resolution and chip dimensions.
* Raster-grid alignment or affine transforms.
* Exact chip-center coordinates.
* Any existing chip-window or AOI geometry definitions.

If native-grid geometry can be reconstructed without downloading raster assets:

1. Build the actual projected chip polygons using the documented CRS and grid alignment.
2. Transform the polygons appropriately for distance calculations.
3. Compute minimum cross-fold polygon-to-polygon distances using a defensible geospatial method.
4. Compare results with the existing WGS84 approximation.
5. Identify all cross-fold pairs near the 50 km threshold.
6. Report the closest pair, its chip IDs, folds, center distance, footprint distance, and margin.
7. Verify whether the current 50.0079 km minimum remains valid under the reconstructed geometry.

Do not invent affine transforms, pixel origins, or exact raster alignment if they are unavailable.

If the repository does not contain enough information to reconstruct native-grid footprints, explicitly classify native-raster verification as **BLOCKED**. State exactly which metadata or source artifact is missing and how it can be obtained without bulk imagery acquisition.

Do not modify fold assignments or the manifest.
